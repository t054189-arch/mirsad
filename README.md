# مرصاد · MIRSAAD

منصة تجريبية لإدارة وتحليل بيانات فحص المنشآت. موقع ثابت يعمل بفتح `index.html` مباشرة في المتصفح — بدون تثبيت أو خادم أو خطوة بناء.

A static demo site for structural inspection management. No build step.

| الملف | المحتوى |
| --- | --- |
| `index.html` | **بوابة الدخول وإنشاء الحساب** — أول ما يُفتح |
| `app.html` | التطبيق (كان `index.html` سابقًا) |
| `app.css` · `app.js` | التطبيق بالكامل — **لم يُمسّا** |
| `auth.css` · `auth.js` | تنسيقات البوابة ومنطقها |
| `guard.js` | يمنع فتح أي صفحة قبل تسجيل الدخول |
| `step-1…5.html` | خطوات الفحص، كل خطوة صفحة مستقلة |
| `steps.css` · `steps.js` | تنسيقات صفحات الخطوات ومنطقها |
| `tools/make-steps.py` | يولّد صفحات الخطوات من هيكل واحد |

## الدخول أولًا

`index.html` هي البوابة، وفيها تبويبان: **تسجيل الدخول** و**إنشاء حساب**.
لا تُفتح أي صفحة أخرى قبلها — `guard.js` يعيد أي زائر غير مسجّل إلى البوابة،
سواء فتح `app.html` أو أي مسار داخلها (`#/dashboard`, `#/sites`, …) أو أي
صفحة من صفحات الخطوات.

### الحساب التجريبي

| | |
|---|---|
| البريد | `dalal@mirsaad.demo` |
| كلمة المرور | `mirsaad2026` |

ومعه زر يملأ الحقلين ويدخل بضغطة واحدة. ولإضافة حساب: تبويب «إنشاء حساب»
(الاسم، البريد، الدور في المكتب، كلمة المرور وتأكيدها).

البوابة تكتب الجلسة بالشكل نفسه الذي يكتبه التطبيق:

```js
localStorage["mirsaad.session"] = '{"userId":"usr-001","email":"…"}'
```

فيتعرّف التطبيق على المستخدم فور دخوله. واللغة مشتركة عبر `mirsaad.locale`،
فالبوابة والتطبيق على لغة واحدة دائمًا.

### ⚠️ هذه بوابة عرض لا حماية

لا يوجد خادم: الصفحات كلها منزّلة أصلًا إلى متصفح الزائر، ويمكن تجاوز البوابة
بسطر واحد في أدوات المطوّر. كلمة مرور الحساب التجريبي مكتوبة في `auth.js`،
والحسابات المنشأة تعيش في متصفح واحد فقط لغياب قاعدة بيانات مشتركة
(كلمة المرور تُخزَّن مُجزّأة لا نصًا صريحًا، لكن التجزئة بسيطة وقابلة للكسر).

للحماية الحقيقية: مصادقة على خادم — مثلًا `supabase.auth` مع Row Level Security.

## خطوات الفحص — كل خطوة صفحة

معالج الفحص الذي كان ثلاث خطوات داخل صفحة واحدة (`#/inspections/new`) صار
خمس صفحات مستقلة، لكل واحدة عنوانها ورابطها:

`step-1` بيانات الفحص ← `step-2` رفع البيانات ← `step-3` التحليل ←
`step-4` المراجعة ← `step-5` السجل والإشعار

- شريط علوي يبيّن الخطوة الحالية والمكتملة.
- «موافقة» في المراجعة تنتقل إلى السجل، و«رفض/تعديل» تبقى في المراجعة.
- صفحة التحليل تتقدّم ثم تفتح زر التالي.
- زر «إجراء فحص جديد» داخل التطبيق يفتح `step-1.html` بدل المعالج القديم.

بعد تعديل `tools/make-steps.py` أعد البناء:

```bash
python3 tools/make-steps.py
```

## التشغيل

افتح `index.html` في أي متصفح حديث، مع إبقاء كل الملفات في المجلد نفسه.

للنشر على الإنترنت: ارفع الملفات إلى أي استضافة ثابتة (GitHub Pages أو Netlify أو Vercel أو استضافة عادية عبر FTP).

> **عند إعادة بناء التطبيق:** أداة البناء تكتب `index.html` — وهي الآن البوابة.
> اجعل ناتج البناء يذهب إلى `app.html`، أو أعد نسخ البوابة بعد كل بناء،
> وإلا سقطت الحماية بصمت.
